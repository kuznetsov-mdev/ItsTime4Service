# План разработки ItsTime4Service (KMP)

## Контекст

Название приложения для пользователя — «Пора на ТО» (английский и испанский — «It’s Time 4 Service»); прежнее рабочее имя PitStop занято в RuStore. В коде проект называется `ItsTime4Service`, пакет — `ru.kuznetsov.itstime4service`.

Проект `ItsTime4Service` (Android + iOS, Kotlin Multiplatform) сейчас — это чистый wizard-скаффолд: `shared/src/commonMain` содержит только дефолтные `App.kt`/`Greeting.kt`/`Platform.kt`, `androidApp` и `iosApp` уже корректно хостят общий Compose-экран (`MainActivity` → `setContent { App() }`, `ContentView.swift` → `MainViewController()`), но никакой прикладной логики, экранов, темы или данных ещё нет.

Цель — пошагово построить приложение по дизайн-макету (`docs/index.html`): сначала design-tokens и переиспользуемые компоненты, затем экраны на фейковых данных, затем domain/data слой и связка через domain, затем уведомления и полировка. Подключение каждой новой библиотеки привязано к конкретному шагу, на котором она впервые понадобится — ничего не тянем заранее "про запас".

**Важное отличие от исходного предположения в задаче:** Compose Multiplatform **уже подключён и настроен** в `shared/build.gradle.kts` — плагины `composeMultiplatform`/`composeCompiler` применены, а `compose.{runtime,foundation,material3,ui,components.resources}` и `androidx.lifecycle.{viewmodelCompose,runtimeCompose}` уже объявлены в зависимостях `commonMain`. Отдельный шаг "подключить Compose Multiplatform" не нужен — этап 1 сразу переходит к написанию тем/токенов.

## Структура пакетов

Базовый пакет: `ru.kuznetsov.itstime4service` (`shared/src/commonMain/kotlin/ru/kuznetsov/itstime4service/`).

Как и просил пользователь — `features`, `domain`, `data`, `di`. Плюс один дополнительный пакет `ui` — для темы, переиспользуемых компонентов и иконок, которые не относятся ни к одной конкретной фиче и нужны до того, как появится хоть один экран:

```
ru.kuznetsov.itstime4service/
├── ui/
│   ├── theme/        # Color.kt, Type.kt, Theme.kt, Dimens.kt
│   ├── components/   # ComponentPreview.kt (общий @Preview-хелпер) + подпакеты по группам из каталога макета:
│   │   ├── buttons/      # PrimaryButton, Fab, AppIconButton, PresetChip, SegmentedControl, TabBarItem
│   │   ├── fields/       # AppTextField, AppNumberField, LabeledMiniField, InlineEditField
│   │   ├── steppers/     # Stepper
│   │   ├── indicators/   # AppSwitch, StatusChip, ProgressBar, GaugeRing
│   │   ├── cards/        # ListRowCard, StatCard, NotificationPreviewCard
│   │   ├── dialogs/      # ConfirmDialog
│   │   └── screen/       # ScreenTopBar, ScreenTitle — общая шапка экранов
│   ├── format/        # форматирование чисел/дат/расстояний, TaskStatus → StatusTier
│   └── icons/         # ItsTime4ServiceIcons.kt — иконки из макета как ImageVector
├── domain/
│   ├── model/         # Car, MaintenanceTask, ServiceHistoryEntry, TaskStatus, TaskStat
│   ├── usecase/        # CalculateTaskStatus, SortedTaskStats, CarAlerts, MarkTaskDone...
│   └── repository/    # интерфейсы: CarRepository, ServiceHistoryRepository, SettingsRepository
├── data/
│   ├── local/          # SQLDelight driver (expect/actual), .sq-схемы
│   ├── repository/     # *RepositoryImpl на SQLDelight (этап 7; до него — Fake*RepositoryImpl)
│   └── mapper/         # маппинг SQLDelight-строк ↔ domain-модели
├── AppViewModel.kt    # тема из настроек для корневого `App`
├── di/                # Koin: FeatureModule.kt, DomainModule.kt, DataModule.kt (по модулю на файл) + Koin.kt (initKoin)
└── features/
    ├── navigation/      # Destinations, NavGraph
    ├── cars/            # экран "Мои авто"
    ├── carform/         # форма авто: "Добавление авто" и "Редактирование авто"
    ├── cardetail/       # экран "Регламентные работы"
    ├── history/         # экран "История ТО"
    └── settings/        # экран "Настройки"
```

ViewModel-ы — `StateFlow<UiState>`, экран подписывается через `collectAsState()`; DI — Koin, инжект через `koinViewModel()` прямо в Composable (подтверждено пользователем).

### Этап 8а — Правки дизайна после прогона
**Библиотеки:** не требуются.

Правки по итогам прогона на экране. Согласованное поведение:

1. **Обязательные поля.** Кнопка «Сохранить» в форме авто всегда активна. По нажатию пустые обязательные поля получают красную рамку, форма не сохраняется; рамка пропадает, когда поле заполнили. Обязательные: марка, пробег, а у работы (в блоке формы авто и на экране работы) — название, интервал замены и «Последний раз, км». У «Последний раз, км» нет значения по умолчанию: пользователь вводит его сам, 0 допустим (работа ещё не проводилась). Молчаливый пропуск незаполненных блоков уходит: ненужный блок удаляется корзиной.
2. **Отметить выполненной.** Первое нажатие открывает модальное окно с тремя необязательными полями: «Где обслуживались», «Сколько стоило», «Комментарий». «Отмена» — работа не отмечается; «Сохранить» — отмечается, в том числе с пустыми полями.
3. **Снять отметку.** Работа считается отмеченной, пока пробег авто равен тому, на котором её отметили; кнопка в это время показывает «Выполнено». Нажатие на неё открывает окно «Вы уверены, что хотите снять отметку о выполнении работ?» с кнопками «Ok» и «Отмена». «Ok» — полный откат: работа возвращается к прежним «последний раз, км» и дате, запись из истории ТО удаляется.
4. **Пробег в карточке авто.** Карандаш убирается, иконка слева крупнее, значение сдвинуто вправо и кликабельно: по тапу превращается в поле ввода с текущим пробегом и галочкой справа для сохранения.
5. **Работа открывается по тапу.** В строке работы сводка под названием идёт по строкам: «осталось N км» (или «просрочено на N км»), с новой строки «или N мес» (или «время истекло», если у работы есть интервал по времени), с новой строки «каждые N км». Каждая строка списка работ на экране авто кликабельна и открывает экран «Редактирование работы» с полями этой работы. Работа удаляется корзиной на этом экране, с подтверждением; записи истории ТО остаются.
6. **Новая работа — через FAB.** Карандаш в топ-баре экрана авто убран; вместо него на экране кнопка «+», она открывает экран «Новая работа» (те же поля и чипы пресетов). Над «Сохранить» на этом экране — кнопка «Добавить ещё»: сохраняет текущую работу и оставляет пользователя на экране с пустой формой для следующей; при пустых обязательных полях ведёт себя как «Сохранить» — подсвечивает их и ничего не сохраняет. Кнопка контурная: текст и рамка цвета фона кнопки «Сохранить» (`accent`), фон — фон экрана. На экране редактирования работы её нет.
7. **Название и VIN правятся на месте.** Тап по названию авто или по VIN превращает текст в поле ввода с галочкой, как у пробега. Между названием и VIN — вертикальный отступ (в макете 10 px), чтобы их подчёркивания не слипались; он сохраняется и в режиме правки. Название и пробег обязательные: пока поле пустое, галочка неактивна (красной рамки здесь нет). Пустой VIN допустим. На экране авто одновременно редактируется только одно поле из трёх (название, VIN, пробег). Значение сохраняет только галочка. Тап мимо поля — по другому полю, строке работы, кнопке или пустому месту — завершает правку и возвращает полю исходное значение, это правило одно для всех трёх полей; то, по чему тапнули, срабатывает как обычно (другое поле открывается на правку).
8. **История ТО по годам и месяцам.** Записи идут от новых к старым и сгруппированы: год — разделитель с числом по центру и линиями до краёв экрана; месяц — рамка с подписью месяца в разрыве верхней линии слева, внутри рамки записи этого месяца; фон внутри рамки светлее фона экрана (`surface`, как у остальных карточек). Подпись месяца — плашка со скруглёнными краями, с тем же фоном и такой же тонкой рамкой, что у карточки; стоит на её верхней линии слева. При прокрутке разделитель года, записи которого сейчас на экране, закреплён у верхнего края списка, пока его не сменит следующий год. В макете следующий разделитель накрывает предыдущий; в приложении допустимо стандартное поведение закреплённых заголовков списка (выталкивание). Каждая запись кликабельна и открывает окно с её данными: заголовок — название работы, под ним авто; ниже пять полей, которые можно править, — «Дата» и «Пробег, км» (обязательные, в одной строке), «Где обслуживались», «Сколько стоило, ₽», «Комментарий»; кнопки «Отмена» и «Сохранить». Неверная дата или пустой пробег не сохраняются и подсвечиваются красной рамкой. Правка записи не меняет саму работу; если у записи изменили пробег, она перестаёт считаться отметкой о выполнении — снять отметку по ней уже нельзя. Отдельного поля «Что менялось» нет: дополнительные сведения пользователь пишет в комментарии.
9. **Прокрутка к новой работе в форме авто.** Когда при создании авто добавляется блок работы — чипом пресета или кнопкой «Добавить произвольную работу», — форма прокручивается к новому блоку так, чтобы он был виден целиком.
10. **Авто при запуске.** Приложение запоминает последнее открытое авто и при следующем запуске сразу открывает его карточку; «назад» с неё ведёт в список авто. В настройках — группа «Запуск» с пунктом «Открывать по умолчанию»: при включении под ним появляется список добавленных авто, выбранное из них открывается при каждом запуске вместо последнего открытого. Если авто нет ни одного, пункта в настройках нет. Если запомненного авто больше нет, открывается список. При удалении выбранного по умолчанию авто вместо него выбирается другое (последнее открытое, а если его нет — первое в списке); если авто не осталось, настройка выключается.
11. **История — общий раздел.** История ТО вынесена в отдельную вкладку нижнего меню. Порядок вкладок — «История», «Авто», «Настройки», у каждой иконка над подписью (часы, автомобиль в профиль, шестерёнка); стартовый экран по-прежнему «Авто». Раздел показывает записи по всем авто. Удаление авто больше не удаляет его историю: авто и его работы удаляются, записи остаются, а само авто в истории показывается серым с пометкой «[продано]».
    - Вверху всегда поле выбора авто на всю ширину, справа от него кнопка фильтра. В выпадающем списке — «Все авто», все авто и проданные (серые, «[продано]»).
    - Фильтр (окно по кнопке): период «с — по», поиск по ключевым словам в названии работы (по вхождению: запрос ищется как подстрока названия, без учёта регистра), диапазон пробега «с — по»; «Сбросить» и «Применить». При активном фильтре кнопка подсвечена. Фильтр и выбор авто действуют вместе.
    - В режиме «Все авто» в каждой записи показано название авто.
    - Проданное авто хранится так же, как обычное, с признаком «продано»: на основном экране и в выборе «по умолчанию» его нет, оно нужно только для истории.
    - В карточке записи сверху вид работы и дата, под ними строка «авто · пробег · стоимость · сервис», ниже комментарий.
    - Группировка по годам и месяцам, закреплённый год и окно записи работают как раньше; если под фильтр ничего не попало — «Ничего не найдено — измените фильтр».
    - Часы на карточке авто остаются: открывают вкладку «История» с уже выбранным этим авто.
12. **Полное удаление авто — в настройках.** В настройках внизу раздел «Удаление авто»: список всех авто, включая проданные, у каждого кнопка-корзина. Она открывает окно «Удалить {марка} полностью?» — авто, его работы и вся история ТО удаляются без возможности восстановления. Если удалять нечего, раздела нет. Окно удаления на карточке авто по-прежнему просит подтверждение и сообщает, что история сохранится, а полностью удалить авто вместе с историей можно в настройках.
13. **Расстояния в выбранных единицах.** Если в настройках выбраны мили, в милях показываются все расстояния в приложении без исключений — пробег, остаток до работы, интервалы, история, списки в настройках, пример уведомления, шаг «напоминать заранее», сами уведомления — и в милях же вводятся; при сохранении они пересчитываются в километры, в которых данные хранятся. Это касается пробега авто (форма и правка на месте), интервала работы, «Последний раз», окна напоминания, пробега в записи истории, диапазона пробега в фильтре и шага «напоминать заранее» в настройках. Подписи полей меняются вместе с единицами («Пробег, км» → «Пробег, мили»). Расхождение в ±1 км из-за округления при пересчёте допустимо. Поле, значение которого не меняли, при сохранении всё же не пересчитывается: от точного равенства пробегов зависит правило «работа отмечена», и сдвиг на километр при простом открытии и сохранении работы снимал бы отметку.
