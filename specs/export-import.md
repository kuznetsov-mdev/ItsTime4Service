# Постановка на разработку: экспорт и импорт 1.1.0

**Обновлено 10.11.2026. Продуктовая постановка основана на согласованных требованиях и одобренных замечаниях UX-ревью. 10.11.2026 пользователь разрешил реализацию по исправленному макету и постановке. Технические предложения требуют проверки совместимости на этапе 1.**

Основание — [согласованные требования](../docs/research/export-import-iteration-3.md). Первые две итерации сохраняют историю выбора, а третья имеет приоритет при противоречиях. [Интерактивный макет](../docs/index.html#interactiveApp) использует стиль приложения и демонстрационные состояния; он не выполняет настоящего чтения, шифрования или сохранения файлов.

Цель — дать пользователю перенести собственные данные на другое устройство и поделиться списком регламентных работ без случайной передачи личных сведений. Этот файл — основная постановка для разработчика: состав, сценарии, правила и критерии приёмки. [План реализации](../docs/superpowers/plans/2026-11-09-export-import.md) задаёт зависимости этапов и проверки, не заменяя продуктовые правила. Отдельная дублирующая постановка не требуется.

## 1. Область версии

Две платформы: Android и iOS, обмен в обоих направлениях. Два состава: полная личная копия и выборочный перенос одной машины. Восстановление полной копии предлагает замену или объединение. Все действия ручные, офлайн, без собственного облака, аккаунта и обязательных платных сервисов.

Не входят автоматические копии, расписание, ротация файлов, постоянное сохранение паролей/ключей, сетевой подбор, PDF, таблицы и импорт чужих форматов. Версия приложения остаётся `1.0.0 (2)` до фактической подготовки нового релиза; один только макет не меняет её на `1.1.0`.

## 2. Точки входа и навигация

- «Настройки → Данные и перенос»: «Сохранить полную копию», «Импорт из файла», «Передать регламент». Блок «Данные» расположен после блока «Запуск», перед блоком «Уведомления».
- Единый вход «Импорт из файла»: приложение определяет тип по содержимому файла, после расшифровки для защищённого файла. Предпросмотр явно показывает определённый тип. Полная копия предлагает объединение или замену; выборочный файл — выбор автомобиля и работ, а при наличии личных групп — отдельные решения об их применении. Пользователь не выбирает тип вручную; имя и расширение не заменяют проверку содержимого. На экране одна кнопка «Выбрать файл», открывающая системный выбор; списка типов или демонстрационных файлов в интерфейсе приложения нет. В HTML-макете кнопка открывает имитацию системного окна Android: папка «Загрузки», один тестовый файл «Пора-на-ТО.it4s», выбор файла, «Открыть» и «Отмена». Без выбора кнопка открытия недоступна. Тип тестового файла соответствует последнему сохранению в макете, до первого сохранения — регламент. После открытия автоматически показывается предпросмотр либо запрос пароля. Отмена возвращает к импорту без изменений. В Android используется системный Storage Access Framework (SAF), без `READ_EXTERNAL_STORAGE` и широкого доступа ко всем файлам. Системное разрешение на хранилище не запрашивается; пояснение об имитации находится за пределами телефона.
- Подсказка полной копии: «Перенести свои данные на другое устройство». Подсказка передачи регламента: «Поделиться списком работ с другим пользователем». На следующих экранах уточняются состав полной копии и возможность отдельно включить личные сведения.
- На экране автомобиля — действие «Передать» с уже выбранной машиной. Оба входа используют один сценарий.
- Возврат из системного выбора — отмена без ошибки. Выбор другого файла или целевого автомобиля сбрасывает решения о совпадениях, личных полях и связанных конфликтах; следующий предпросмотр строится заново. Решение для одной машины нельзя применить к другой.
- После завершения импорта корневые вкладки читают обновлённые данные, повторное нажатие не повторяет запись. Кнопка завершения и возврат со страницы успеха закрывают сессию и ведут в исходный раздел; они не возвращают к применению прежнего плана.
- В первой поставке гарантируется импорт через системный выбор внутри приложения. Открытие вложения из другого приложения может вести в тот же процесс после отдельной проверки Android intent/UTType; это не заменяет основной путь.
- Пароли, содержимое файла, VIN, номера и решения конфликтов не входят в route, deep link, saved state или логи. Route содержит только неперсональный идентификатор текущей сессии.

Предлагаемые маршруты: `settings/data`, `transfer/export`, `transfer/import`; машина для экспорта передаётся существующим ID через аргумент, а не содержимым данных. Последовательные шаги принадлежат одной ViewModel, чтобы возврат не запускал импорт повторно. Смена темы не сбрасывает выбор состава; после завершения/отмены секреты очищаются. После смерти процесса операция начинается с безопасного повторного выбора/чтения файла, а уже завершённый импорт распознаётся по записи его результата.

## 3. Матрица состава

| Данные | Полная копия | Выборочная передача |
|---|---|---|
| Действующие и проданные машины, порядок | Все | Одна выбранная машина |
| Марка/модель | Да | Да |
| Параметры работ, иконки | Все | Выбор работ, изначально выбраны все |
| Текущий пробег, VIN, госномер | Да | Три отдельных выключенных переключателя |
| Последний пробег/дата обслуживания | Да | Отдельная выключенная группа |
| История: названия, даты, пробеги | Да | Отдельная выключенная группа всей истории выбранной машины |
| Стоимость, сервис, комментарии истории | Да | Дополнительная выключенная подгруппа; доступна только с историей |
| Настройки, скрытие полей, данные отката и значимый порядок | Да | Настройки/скрытые значения не передаются; допустимые связи личной истории определяются включёнными группами |
| Параметр «Напоминать за…» | Сохранённые значения | Новым работам — настройка получателя; существующим — свой порог |
| Описание модификации, условий и источника | Сохранённое описание | Необязательное описание автора, без автоматического статуса «проверено» |
| Системное разрешение, задания ОС, пути файлов | Нет | Нет |

Полный состав включает сохранённые индивидуальные пороги напоминаний, описание регламента, допустимые данные отката отметок и состояние уже показанных напоминаний, нужное для предотвращения повторного показа. Задания ОС восстанавливаются по данным, текущей дате и разрешениям получателя. Полная копия содержит историю вручную добавленных событий и удалённых работ, а не только сведения из видимых списков.

Скрытый в интерфейсе номер не означает разрешение на экспорт его исходного значения. Отсутствующая группа означает «не передавать/не менять», а не `null`, пустую строку или команду удаления. История и последнее обслуживание независимы. Невыбранная работа не создаётся автоматически через историю. История удалённой работы допустима и остаётся историей без действующей работы.

## 4. Сценарии интерфейса

### Экспорт

1. Выбор полной копии либо машины и состава. Для работ — выбор всех/отдельных. Дополнительные группы по умолчанию выключены.
2. Для полного или личного выборочного файла защита паролем включена. Пользователь может явно выключить её; предупреждение перечисляет риск открытого содержимого. Чистый регламент по умолчанию открыт; настройка его защиты вторична и не затрудняет основной сценарий. Включение личной группы включает защиту по умолчанию; явный отказ от защиты требует предупреждения.
3. При включённой защите — пароль и подтверждение. Пароли не обрезаются и не меняют регистр. Конкретная политика длины и совместимость Unicode входят в техническую проверку перед реализацией.
4. Предпросмотр состава. Описание автора и источник не подменяются утверждением производителя. Произвольный текст отправитель проверяет сам.
5. Формируется согласованный снимок, открывается системное сохранение или передача. «Сохранено» показывается после подтверждённой записи. Отмена передачи не означает, что получатель получил файл.

### Импорт полной копии

1. Выбор файла, проверка ограниченного заголовка и версии; для зашифрованного файла — ввод пароля до просмотра личного содержимого.
2. Предпросмотр числа действующих/проданных машин, работ и истории, даты копии. Выбор «Объединить» или «Заменить всё»; «Восстановить настройки» включено по умолчанию.
3. Объединение: сопоставление всех машин копии, затем существенные конфликты каждой из них; один общий итог и одна атомарная запись всего подтверждённого состава. Нельзя ограничить восстановление первой машиной файла. Одинаковая марка/VIN не дают права молча объединить сущности. Отсутствие объекта в копии не означает удалить его на устройстве.
4. Замена: отдельное предупреждение о полном составе потери. Предлагается сохранить текущую копию; можно явно продолжить без неё. Отмена/ошибка сохранения страховочной копии не отмечает её сохранённой. Последнее подтверждение доступно после успешной страховки либо явного отказа от неё.
5. Итоговый список добавлений, замен, пропусков, настроек и ограничений отмены отметок. При замене нет решений «Пропустить»/«Обновить»/«Добавить отдельную»: полный состав копии заменяет данные целиком, с отдельным выбором восстановления настроек. Запись — одна целостная операция.
6. Пересоздание уведомлений. Если планировщик не сработал после commit БД, данные уже восстановлены: повторяется настройка уведомлений, а не импорт.

### Импорт выборочного файла

1. Показать фактический состав, описание применимости/источник. Получатель выбирает свою машину или создаёт новую.
2. Целевой автомобиль подтверждается кнопкой «Выбрать этот автомобиль» или «Создать автомобиль». Для новой машины запросить/подтвердить фактический текущий пробег до сохранения: переданное значение можно предварительно заполнить; при отказе от него необходимо ввести своё. Для существующей непереданные сведения сохраняются.
3. Выбор работ. Для совпадения: «Пропустить» (по умолчанию), «Обновить параметры», «Добавить отдельную». Обновление регламента сохраняет собственные факты обслуживания.
4. Личные сведения, если отправитель включил их, применяются отдельно и явно. Разногласия: «Оставить текущее» (по умолчанию) / «Взять из файла»; для новой машины — «Не переносить» / «Взять из файла». Пробег новой машины подтверждается на шаге назначения, без повторного решения на следующем экране. Стоимость/сервис/комментарии следуют решению истории только при включённой подгруппе. Отсутствующие группы не показываются как доступные данные.
5. Если нет ни совпадений работ, ни личных/связанных решений, сразу открыть итоговый предпросмотр с пояснением «Совпадений нет». При наличии любого необходимого решения шаг не пропускается.
6. Последнее обслуживание новой работы без сведений — «Не знаю». История не используется для молчаливого вывода непереданного последнего обслуживания.
7. Итог, явное подтверждение, атомарная запись и пересчёт уведомлений.

## 5. Неизвестное обслуживание

Минимальная поддержка входит уже в `1.1.0`. Предлагаемая модель: последний пробег может отсутствовать; отсутствие даты отличается от неприменимости временного критерия. Ноль, явно сохранённый в старой БД, автоматически в «неизвестно» не превращается. Новые импортированные неизвестные значения нулём не заполняются.

UI: выбор «Не знаю» / «Указать пробег и дату», рекомендация «Рекомендовано обслужить» без вымышленных километров просрочки. Известная просрочка по другому критерию не скрывается. Неизвестный критерий не даёт числового прогресса. Статусы сортируются явными правилами, не порядком enum. При записи фактического выполнения последнее обслуживание становится известным.

До реализации в основном `specs/domain.md` нужно зафиксировать nullable-результаты расчёта, приоритет рекомендации, отображение счётчиков/колец и политику уведомлений для одной только рекомендации. Это техническая/UX-доработка согласованного статуса; текущая спецификация расчётов не меняется молча.

## 6. Связи, конфликты и запись

Полный снимок сохраняет UUID, логический порядок и допустимые исторические ссылки/данные отката. Выборочный файл использует локальные идентификаторы внутри файла; исключённые личные данные не просачиваются через служебные поля. Импорт создаёт явное соответствие входных и локальных сущностей.

Связанные изменения истории и последнего обслуживания проверяются как согласованная группа (в UI — «Последнее обслуживание и история» только для действительно связанных конфликтных фактов, не по одному наличию обеих групп): нельзя независимо выбрать несовместимые половины связи. Согласованное пользователем решение показывается в итоговом плане до записи. При конфликте «продан/действующий» показываются последствия для работ; проданная машина не хранит скрытых действующих работ. При отсутствии конфликта допустимый старый откат сохраняется; конфликтующий откат отключается без потери исторической записи.

Подтверждение связывается с отпечатком текущего состояния БД и входного снимка. Перед записью внутри транзакции отпечаток проверяется снова. При изменении данных возвращается актуальный предпросмотр, а не применяется старое решение. Идентификатор операции и её результат записываются в той же транзакции, чтобы повторное нажатие/перезапуск после завершения не дублировали импорт. Осознанная команда «Добавить отдельную» остаётся отдельным подтверждённым действием.

## 7. Предлагаемый контракт файла и защита

Это техническое предложение к утверждению после проверки совместимости, не обещание уже реализованного формата.

- Расширение `.it4s`, MIME `application/octet-stream`; JSON UTF-8 как логическая полезная нагрузка, не копия файла SQLite. Два `kind`: `backup` / `car`; `formatVersion=1` независимо от версии БД/приложения. Единицы — целые километры и рубли как в существующей модели, даты — ISO `YYYY-MM-DD`; версия/идентификатор снимка и включённые группы обязательны.
- Размер ограничивается до полного чтения. Начальный предлагаемый предел файла — 16 MiB; заголовка — 4 KiB; расшифрованной нагрузки — 10 MiB. Сжатие в версии 1 не требуется. Ошибка лимита не меняет БД. Числа, глубина и количества коллекций имеют явные пределы в валидаторе; незнакомая новая версия отклоняется с предложением обновить приложение.
- Для личного файла требуется аутентифицированное шифрование. Кандидат: AES-256-GCM с PBKDF2-HMAC-SHA256, 600 000 итераций, соль 16 байт, nonce 12 байт, tag 128 бит. Криптографически случайные соль и nonce создаются заново; заголовок версии/алгоритма аутентифицируется. Произвольные параметры KDF из файла до валидации не выполняются. Открытый файл не получает ложного признака криптографической подлинности.
- Заголовок зашифрованного файла не содержит машин, VIN, номеров, истории или их количества. Ошибка аутентификации не позволяет достоверно отличить неверный пароль от повреждения: текст «Не удалось открыть защищённый файл. Проверьте пароль или выберите другую копию».
- Пароль/ключ живут только в текущей операции; их нет в saved state, именах файлов, логах, резервной копии или постоянном хранилище. Временные данные допускаются только в закрытом каталоге приложения с определённым сроком жизни; политика очистки не затрагивает пользовательские файлы. Выбор исходного файла сам по себе его не удаляет и не перезаписывает.

Кандидат-библиотека — [cryptography-kotlin](https://whyoleg.github.io/cryptography-kotlin/getting-started/); её [рецепт парольного шифрования](https://whyoleg.github.io/cryptography-kotlin/primitives/recipes/password-based-encryption/) использует PBKDF2 и AES-GCM. Это подтверждает наличие подхода, но не заменяет проверку Android API 24, iOS, релизного R8 и производительности. Точный бинарный конверт, UTF-8 пароль, ограничения и правила presence зафиксированы в [transfer-format v1](transfer-format.md); фактически выполненные native crypto проверки и открытые release gates — в [отчёте совместимости](../docs/research/transfer-format-compatibility.md). cryptography-kotlin 0.6.0 сначала проверена только в test source sets Task 1B; на этапе 4 её зависимости подключены к runtime source sets. Кодек использует kotlinx-serialization-json 1.12.0 за строгим структурным reader без аннотаций на domain-моделях. Для iOS используется API + prebuilt-nativebuilds с явной строгой версией libcrypto 3.6.5 вместо старой встроенной 3.6.0. Поддержка всех минимальных ОС обязательна; скрыто повышать minSdk ради библиотеки нельзя. Состав и опубликованные версии повторно проверены 10.11.2026.

## 8. Предлагаемые границы реализации

- `domain/transfer`: снимки, состав экспорта, варианты конфликтов, план и результат импорта. Доменные модели не зависят от JSON, Android URI, iOS URL, Compose и криптобиблиотеки.
- `data/transfer`: DTO/валидатор/кодек/шифрование и репозиторий целостного снимка, импорта и соответствий. Чтение/запись БД — существующий последовательный dispatcher и транзакции.
- `ui/transfer`: семантический порт системного выбора/сохранения/передачи файлов. Реализации в Android/iOS source set; отмена, отказ доступа и ошибка результата различаются.
- `features/transfer`: экран данных и мастера экспорта/импорта. Общий plain content принимает state и callbacks; ViewModel владеет текущей операцией, секреты не включаются в сериализуемое состояние.
- `di/TransferModule.kt`: общие привязки; нативные адаптеры — существующий `platformModule`.

Предлагаемые контракты для подробного плана: `TransferRepository.readSnapshot(): TransferSnapshot`, `prepareImport(request): ImportPlan`, `applyImport(plan): ImportResult`; `TransferCodec.encode/decode`; `TransferCipher.seal/open`; `TransferFiles.pick/read/save/share`. Сигнатуры suspend, типы ошибок, владение файловыми дескрипторами и cancellation фиксируются в первом техническом шаге, до кодирования вызывающих слоёв.

## 9. Проверки и условия перехода к коду

Базовые критерии ниже сохраняют нумерацию согласованной третьей итерации для трассировки с планом. Приёмка выполняется на Android и iOS, включая обмен в обоих направлениях.

1. Совместимый полный снимок восстанавливается Android → iOS и iOS → Android с сохранением подтверждённого состава, связей, значимого порядка и допустимого отката. Проверяются активные/проданные машины и история удалённой работы.
2. При замене старые данные меняются только после актуального предпросмотра, предложения страховочной копии и явного окончательного подтверждения. Отказ от страховки допустим; ошибка записи не оставляет полузаменённую базу.
3. При объединении новые сущности добавляются, а разногласия решаются отдельно с текущими значениями по умолчанию. Одно название/VIN не вызывает скрытое объединение. Отсутствующие в файле сведения не удаляют текущие.
4. Включённое восстановление настроек выбирает настройки файла при обоих режимах; выключенное сохраняет настройки устройства. Сопоставление ссылок на машины и действующие разрешения проверяются отдельно.
5. Выборочный экспорт по умолчанию содержит только согласованный регламент/марку и доступные сопроводительные сведения; ни личные факты, ни скрытые значения не просачиваются через служебные поля. По отдельности проверяются все переключатели и зависимость подробностей от истории.
6. Выбор работ на обеих сторонах изначально включает все; отключение работы не создаёт её автоматически через импортированную историю. Новый либо существующий целевой автомобиль выбирается явно.
7. Новая машина без переданного пробега не сохраняется с вымышленным значением. Существующая не теряет собственный пробег/VIN/номер при отсутствующей группе; переданные отличающиеся значения требуют отдельного выбора.
8. Для совпавшей работы доступны «Пропустить», «Обновить параметры» и «Добавить отдельную»; «Пропустить» выбран по умолчанию. Изменение параметров не меняет историю/последнее обслуживание и не создаёт фиктивное выполнение.

Требование сопоставления к критерию 8: когда на телефоне несколько одноимённых работ, «Обновить параметры» предлагает выбрать конкретную работу. Варианты показывают интервал и последнее обслуживание; исходного выбора нет. Итог повторяет выбранную работу. Две входные работы не могут молча обновить одну локальную; для них требуется исправить выбор или пропустить/добавить отдельную. При смене файла/машины сопоставления сбрасываются.
9. Все комбинации истории и последнего обслуживания обрабатываются независимо; неизвестность не становится нулём. Подтверждённые сведения и известная просрочка сохраняются, непереданные факты автоматически не выводятся из истории.
10. Личный полный/выборочный файл защищён по умолчанию; отключение явно подтверждается. Чистый регламент по умолчанию открыт. Неверный пароль не меняет БД; пароль не сохраняется между операциями.
11. Конфликт проданного/действующего состояния не вызывает скрытого удаления или возвращения работ; предпросмотр отражает последствия выбранного состояния, история сохраняется по плану.
12. После конфликтного merge старая отметка затронутой работы не откатывается, история остаётся. Для бесконфликтных работ и полного восстановления сохранён допустимый старый откат; новые отметки отменяются обычно.
13. Повторное открытие файла/подтверждение и восстановление после прерывания не создают неконтролируемых копий. Осознанное «Добавить отдельную» проверяется отдельно от повторной доставки того же импорта.
14. Сохранение/чтение/системная передача работают без собственных аккаунта и сети; отмена, потеря доступа, недоступный файл и нехватка места дают корректный результат. Успех не заявляется до подтверждённого результата операции.
15. После импорта не остаются уведомления заменённых машин; отказ/сбой планировщика не повторяет импорт и не повреждает восстановленные данные. Настройки прав ОС не берутся из файла.
16. Проверены RU/EN/ES, километры/мили и форматы дат; обмен хранит однозначные единицы/даты и не обещает перевода пользовательских названий. Миграции сохраняют существующие данные и прежнее поведение старых подтверждённых записей.
17. В 1.1.0 нет фонового копирования, ротации/автоудаления, постоянного запоминания папки для фонового доступа и сохранения ключа: соответствующие снятые вопросы не превращаются в реализованные возможности.

### Дополнительная приёмка согласованных исправлений UX

- U1. Вход «Импорт из файла» единый, вид определяется по проверенному содержимому. Личный выборочный файл сохраняет фактический состав и показывает отдельные решения применения; его нельзя выдать за обезличенный регламент. Для HTML-демонстрации это проверяется сохранением/повторным открытием mock-файла; в приложении — настоящим файлом.
- U2. После смены файла или машины все решения прежнего назначения сброшены, включая пробег, последнее обслуживание и историю. Предпросмотр отражает только новый состав/цель.
- U3. Замена не выводит решения объединения; итог точно отражает полный состав и выбранный режим настроек. Отмена/ошибка страховки не имитирует сохранение.
- U4. Завершение и возврат со страницы успеха заканчивают операцию; повторного применения из старого экрана нет. Шаг решений пропускается только при отсутствии всех необходимых решений.
- U5. Системный выбор можно отменить без ошибки/изменения данных; Android не запрашивает широкое разрешение хранения. Макетная папка «Загрузки» и файл «Пора-на-ТО.it4s» — только демонстрация выбора, а не требование к содержимому нативного диалога.

### Состояние проверок

Ограничение демонстрации: интерактивное сопоставление при объединении полной копии показывает первую машину; общий предпросмотр и замена могут перечислять все машины. Это не подтверждает многомашинное объединение и не сокращает требование сопоставить все машины перед общей атомарной записью.

Ранее для предыдущих редакций макета сообщались 130, затем 16 и 32 DOM-проверки Chrome. Это исторические результаты, не проверка исправлений от 10.11.2026. 10.11.2026 после исправлений дизайнер и координатор независимо запустили один набор из 77 проверок текущих функций HTML-макета в изолированном JS-окружении: сброс решений, личный состав и применение, итог замены, завершение сессии, пропуск пустого шага, CTA, единое имя файла и копии с проданным автомобилем без работ. Все проверки прошли; синтаксис полного JS и `git diff --check` также проверены. Это не браузерная визуальная проверка и не замена нативных проверок SAF/iOS, реального шифрования, миграций и межплатформенного обмена. 10.11.2026 пользователь разрешил перейти к реализации по исправленному макету.
