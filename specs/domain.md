# Спецификация: domain-слой

Пакет: `ru.kuznetsov.itstime4service.domain` (`shared/src/commonMain/kotlin/ru/kuznetsov/itstime4service/domain/`).

Domain-слой — чистый Kotlin без зависимостей от UI и хранилища. Из библиотек использует только `kotlinx-datetime` (`LocalDate`, `LocalTime`) и `kotlinx-coroutines-core` (`Flow`).

```
domain/
├── model/        # модели
├── usecase/      # бизнес-логика; единственная точка входа для ViewModel-ов
└── repository/   # интерфейсы репозиториев
```

Правило слоя: ViewModel-ы работают только с use case-ами и репозиториев не видят. Use case — класс с одним методом `operator fun invoke(...)`. Все use case-ы зарегистрированы в `domainModule` (`di/DomainModule.kt`).

## Модели

Три группы: **хранимые** (то, что ляжет в базу), **черновики** (то же без `id`, до сохранения) и **вычисляемые** (считаются на лету и нигде не сохраняются).

```
Car ──(tasks, вложены)──▶ MaintenanceTask
 ▲                              │
 │ carId                        │ + пробег машины + сегодняшняя дата
 │                              ▼
ServiceHistoryEntry          TaskStat ──▶ TaskStatus
                                │
                 TaskWithStat = MaintenanceTask + TaskStat
                 CarAlerts    = счётчики TaskStatus по всем работам машины
                 PlannedReminder = работа + её состояние + момент показа уведомления

ServiceHistoryEntry ──(taskId, prev*)──▶ MaintenanceTask   (запись, созданная отметкой, — для отката)
HistoryRecord = ServiceHistoryEntry + CarSummary владельца (в том числе проданного)

Settings ──▶ ThemeMode, DistanceUnit, CarsView; lastOpenedCarId, defaultCarId ──▶ Car
MaintenanceTask ──▶ TaskIcon?            Car.plate ──(DetectPlateStyleUseCase)──▶ PlateStyle
```

### Хранимые

#### `Car`

Машина. Корень: работы живут внутри машины и отдельно от неё не существуют.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `String` | идентификатор, он же аргумент маршрута навигации |
| `brand` | `String` | марка и модель одной строкой |
| `mileageKm` | `Int` | текущий пробег |
| `vin` | `String?` | VIN; `null`, если не указан (прочерк подставляет UI) |
| `tasks` | `List<MaintenanceTask>` | регламентные работы этой машины |
| `plate` | `String?` | госномер как ввели: верхний регистр, пробелы внутри схлопнуты до одного, по краям обрезаны, до 12 символов; `null`, если не указан |

`Car` — всегда действующая машина: проданные в списки машин и на экран машины не попадают.

#### `MaintenanceTask`

Регламентная работа — «правило»: что делать и как часто. Срок наступает по пробегу и, опционально, по времени — что раньше.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `String` | идентификатор |
| `name` | `String` | название работы |
| `intervalKm` | `Int` | интервал по пробегу |
| `lastDoneKm` | `Int` | пробег, на котором работу делали в последний раз |
| `reminderWindowKm` | `Int` | за сколько км до срока статус становится `SOON` |
| `intervalMonths` | `Int?` | интервал по времени |
| `lastDoneDate` | `LocalDate?` | дата последнего выполнения |
| `icon` | `TaskIcon?` | выбранная иконка; `null` — иконку не выбирали |

Срок по времени учитывается, только когда заданы и `intervalMonths`, и `lastDoneDate`.

`TaskIcon` — `WRENCH`, `DROPLET`, `DISC`, `FILTER`, `ZAP`, `BATTERY`, `THERMOMETER`, `TIRE`, `WIND`, `GEAR`, `GAUGE`, `CAR`. Новая работа получает `WRENCH`, в том числе из пресета. `null` — у работ, сохранённых до этапа 8б: экран подбирает иконку по названию; правка такой работы без выбора иконки оставляет `null`.

#### `ServiceHistoryEntry`

Запись в журнале ТО — «факт»: что сделали, когда и на каком пробеге.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `String` | идентификатор |
| `carId` | `String` | машина, к которой относится запись |
| `taskName` | `String` | название работы текстом |
| `date` | `LocalDate` | дата выполнения |
| `mileageKm` | `Int` | пробег на момент выполнения |
| `costRub` | `Int?` | стоимость |
| `serviceName` | `String?` | где делали |
| `comment` | `String?` | комментарий |
| `taskId` | `String?` | работа, отметка которой создала запись |
| `prevLastDoneKm` | `Int?` | `lastDoneKm` работы до отметки — для отката |
| `prevLastDoneDate` | `LocalDate?` | `lastDoneDate` работы до отметки — для отката |

`taskName` хранится текстом, поэтому запись переживает переименование и удаление работы. Записи создаются отметкой о выполнении — у них заполнены `taskId` и `prevLastDoneKm` — или вручную на вкладке «История» (`AddHistoryEntryUseCase`) — у них эти три поля пустые, они не связаны с работой и отметкой не считаются. У записей, созданных до этапа 8а, эти поля тоже пустые, и снять отметку по ним нельзя.

#### `Settings`

Настройки пользователя с экрана «Настройки».

| Поле | Тип | Смысл |
|---|---|---|
| `themeMode` | `ThemeMode` | тема: `LIGHT`, `DARK`, `SYSTEM` (как на устройстве) |
| `distanceUnit` | `DistanceUnit` | единицы показа и ввода: `KILOMETERS`, `MILES` |
| `pushEnabled` | `Boolean` | включены ли push-уведомления |
| `defaultReminderWindowKm` | `Int` | окно напоминания по умолчанию, в км |
| `reminderTime` | `LocalTime` | время ежедневных уведомлений |
| `lastOpenedCarId` | `String?` | машина, экран которой открывали последним |
| `openDefaultCar` | `Boolean` | включён ли пункт «Открывать по умолчанию» |
| `defaultCarId` | `String?` | машина, выбранная для открытия при запуске |
| `carsView` | `CarsView` | вид списка авто: `LIST` (строки), `TASKS` (карточки с работами), `TASKS_AND_HISTORY` (карточки с работами и историей); по умолчанию `LIST` |

Данные всегда хранятся в километрах; `distanceUnit` влияет только на показ и ввод. Ссылки на машины могут указывать на удалённую машину, если сброс по какой-то причине не произошёл: читающие их use case-ы проверяют, что машина есть.

#### `CarSummary`

Машина без работ — для истории и списков в настройках: `id`, `brand`, `mileageKm`, `isSold`. `isSold` — машина удалена с её экрана, а история сохранена: работ у неё нет, на основном экране и в выборе «по умолчанию» она не участвует.

### Черновики

Те же данные без `id`. Идентификатор присваивает репозиторий при сохранении.

| Модель | Отличие от хранимой |
|---|---|
| `NewCar` | нет `id`; `tasks` — список `NewMaintenanceTask` |
| `NewMaintenanceTask` | нет `id`; `reminderWindowKm` может быть `null` — «взять долю интервала по умолчанию»; `icon` по умолчанию `WRENCH`, `null` — оставить работу без иконки |

Черновика записи истории нет: запись отметкой создаёт сам `CarRepository.markTaskDone`, ручную — `ServiceHistoryRepository.addEntry` по полям, переданным по отдельности.

### Вычисляемые

#### `TaskStatus`

Срочность работы: `OK`, `SOON`, `DUE`. Значения объявлены по возрастанию срочности, поэтому худший из двух статусов — `maxOf(a, b)`.

#### `TaskStat`

Состояние одной работы на данный момент. Считается из работы, пробега машины и сегодняшней даты.

| Поле | Тип | Смысл |
|---|---|---|
| `dueAtKm` | `Int` | пробег, на котором наступает срок |
| `remainingKm` | `Int` | сколько км осталось; отрицательное при просрочке |
| `remainingMonths` | `Int?` | сколько месяцев осталось; `null`, если срока по времени нет; ноль или меньше при просрочке |
| `status` | `TaskStatus` | итоговый статус |
| `progress` | `Float` | доля пройденного интервала по пробегу, от 0 до 1 |

#### `TaskWithStat`

Пара «работа + её состояние» (`task`, `stat`). Нужна экрану работ, чтобы показать название и статус в одной строке.

#### `CarAlerts`

Сводка по машине.

| Поле | Тип | Смысл |
|---|---|---|
| `soon` | `Int` | сколько работ в статусе `SOON` |
| `due` | `Int` | сколько работ в статусе `DUE` |
| `taskCount` | `Int` | сколько всего работ у машины |
| `total` | `Int` | вычисляемое: `soon + due` |
| `worstStatus` | `TaskStatus` | вычисляемое: `DUE`, если есть просроченные; иначе `SOON`, если есть «скоро»; иначе `OK` |

#### `HistoryRecord`

Запись истории вместе с машиной-владельцем (`entry`, `car: CarSummary`) — для общей истории по всем машинам.

#### `PlannedReminder`

Одно запланированное уведомление о скорой или просроченной работе: `carId`, `taskId`, `carBrand`, `taskName`, `status`, `remainingKm`, `remainingMonths`, `fireAt: LocalDateTime` (в часовом поясе устройства). Состояние работы — на день показа при пробеге, известном на момент планирования.

#### `PlateStyle`

Вид номерного знака, который определяет `DetectPlateStyleUseCase`: `Russian(series, region)`, `European(countryCode)`, `American`, `Universal`. Правила — в «Расчётных» use case-ах.

#### `ReminderRecord`

След запланированного уведомления в хранилище: `taskId` и `fireAt`. Запись с `fireAt` в прошлом считается уже показанным уведомлением. Единственная из «напоминательных» моделей, которая сохраняется в базу.

## Репозитории

Интерфейсы в `domain/repository/`. Чтение — `Flow`, который переизлучает данные при каждом изменении; изменение — `suspend`-методы. Реализации — на SQLDelight (`data/repository/*RepositoryImpl`).

### `CarRepository`

| Метод | Что делает |
|---|---|
| `observeCars(): Flow<List<Car>>` | действующие машины (без проданных) |
| `observeCarById(carId): Flow<Car?>` | одна действующая машина; `null`, если её нет или она продана |
| `observeCarSummaries(): Flow<List<CarSummary>>` | все машины без работ, проданные в конце |
| `addCar(car: NewCar): String` | сохраняет машину и её работы, присваивает им `id`, возвращает `id` машины |
| `sellCar(carId)` | удаляет работы машины; машину с записями истории помечает проданной, машину без записей удаляет целиком |
| `purgeCar(carId)` | удаляет машину (в том числе проданную), её работы и всю её историю |
| `updateMileage(carId, mileageKm)` | меняет текущий пробег |
| `markTaskDone(carId, taskId, date, serviceName, costRub, comment): Boolean` | ставит работе `lastDoneKm` = текущий пробег машины и, если у неё есть интервал по времени, `lastDoneDate` = `date`; добавляет запись истории с `taskId`, переданными значениями и прежними `lastDoneKm`/`lastDoneDate` работы. `false` и ничего не меняет, если нет машины или работы |
| `unmarkTaskDone(carId, taskId, entryId): Boolean` | возвращает работе `prevLastDoneKm`/`prevLastDoneDate` из записи `entryId` и удаляет запись. `false` и ничего не меняет, если запись создана не отметкой этой работы |
| `updateCar(carId, brand, vin, plate)` | меняет марку, VIN и госномер |
| `addTask(carId, task: NewMaintenanceTask)` | добавляет работу существующей машине |
| `updateTask(carId, task: MaintenanceTask)` | заменяет работу с тем же `id` |
| `deleteTask(carId, taskId)` | удаляет работу |

`sellCar`, `purgeCar`, `markTaskDone` и `unmarkTaskDone` пишут в несколько таблиц одной транзакцией.

### `ServiceHistoryRepository`

| Метод | Что делает |
|---|---|
| `observeHistory(carId): Flow<List<ServiceHistoryEntry>>` | записи одной машины в порядке добавления |

### `ReminderScheduler`

Не хранилище, а выход в систему уведомлений; реализация — `data/notification/ReminderSchedulerImpl` поверх платформенного `LocalNotifications` (Android — отложенные задачи `WorkManager`, iOS — `UNUserNotificationCenter`).

| Метод | Что делает |
|---|---|
| `schedule(reminders, distanceUnit)` | снимает все ещё не показанные уведомления и ставит переданные; пустой список — просто отмена |

### Расчётные

Чистые функции без состояния и без репозиториев. Сегодняшняя дата передаётся параметром `today`.

| Use case | Вход | Выход |
|---|---|---|
| `CalculateTaskStatusUseCase` | `mileageKm`, `task`, `today` | `TaskStat` |
| `SortedTaskStatsUseCase` | `car`, `today` | `List<TaskWithStat>` |
| `CarAlertsUseCase` | `car`, `today` | `CarAlerts` |
| `GetTodayUseCase` | — | `LocalDate` |
| `GetNowUseCase` | — | `LocalDateTime` |
| `PlanRemindersUseCase` | `cars`, `settings`, `now`, `lastShown` | `List<PlannedReminder>` |
| `DetectPlateStyleUseCase` | `plate`, `deviceRegion` | `PlateStyle` |

`SortedTaskStatsUseCase` и `CarAlertsUseCase` своих правил статуса не содержат: оба вызывают `CalculateTaskStatusUseCase` для каждой работы.

`GetTodayUseCase` возвращает сегодняшнюю дату, `GetNowUseCase` — текущие дату и время в часовом поясе устройства. Это единственные места, где domain читает системные часы.

#### Вид номера (`DetectPlateStyleUseCase`)

**Мягкая валидация.** Номер никогда не отклоняется: по его формату только выбирается вид номерного знака. `deviceRegion` — ISO-код страны устройства (`deviceRegion()` в `ui/format`).

| `PlateStyle` | Когда | Что показывается |
|---|---|---|
| `Russian(series, region)` | без пробелов и дефисов совпадает с «буква, 3 цифры, 2 буквы, 2–3 цифры региона»; буквы — `АВЕКМНОРСТУХ` (латинские двойники `ABEKMHOPCTYX` переводятся в кириллицу) | серия «А 123 ВС» и регион с «RUS» и флагом |
| `European(countryCode)` | испанский формат «4 цифры + 3 согласные» → `E`; немецкий «1–3 буквы, пробел или дефис, 1–2 буквы, 1–4 цифры, E/H» → `D`; «2 буквы, 3 цифры, 2 буквы» → `I`, если регион устройства — Италия, иначе `F` | номер с синей полосой и кодом страны |
| по региону устройства | формат не распознан: регион США → `American`; страна ЕС → `European` с кодом этой страны; иначе `Universal` | американский, европейский или универсальный |

Коды стран ЕС на полосе: A, B, BG, HR, CY, CZ, DK, EST, FIN, F, D, GR, H, IRL, I, LV, LT, L, M, NL, PL, P, RO, SK, SLO, E, S. Американские номера фиксированного формата не имеют, поэтому американский вид выбирается только по региону.

#### Правила планирования уведомлений (`PlanRemindersUseCase`)

- Push выключен в настройках → пустой план.
- Уведомления ставятся на «время напоминаний» из настроек. Первый день — сегодня, если это время ещё впереди, иначе завтра; горизонт — 30 дней.
- На каждый день статус работы считает `CalculateTaskStatusUseCase` при текущем пробеге машины и дате этого дня. Поэтому работа с интервалом по времени попадает в план с того дня, когда станет «скоро», даже если приложение больше не открывали; изменение пробега учитывается только после перепланирования.
- Работа со статусом `SOON` или `DUE` получает уведомление, если с предыдущего уведомления о ней прошло не меньше 3 дней. `lastShown` — день последнего уже показанного уведомления по `id` работы.
- План упорядочен по времени и обрезается до 60 самых ранних уведомлений (iOS держит не больше 64 ожидающих).

#### Правила расчёта статуса (`CalculateTaskStatusUseCase`)

По пробегу:

- `dueAtKm = lastDoneKm + intervalKm`, `remainingKm = dueAtKm − mileageKm`.
- `remainingKm ≤ 0` → `DUE`; `remainingKm ≤ reminderWindowKm` → `SOON`; иначе `OK`.
- `progress = (mileageKm − lastDoneKm) / intervalKm`, ограничено диапазоном 0..1; при `intervalKm ≤ 0` равен 0.

По времени (только если заданы `intervalMonths > 0` и `lastDoneDate`):

- Прошло месяцев — число полных месяцев между `lastDoneDate` и `today`: разница по году и месяцу, минус один, если день месяца в `today` меньше, чем в `lastDoneDate`; не меньше нуля.
- `remainingMonths = intervalMonths − прошло месяцев`.
- Окно напоминания в месяцах — окно по пробегу, перенесённое на интервал по времени: `round(intervalMonths × reminderWindowKm / intervalKm)`, но не меньше 1; при `intervalKm ≤ 0` равно 1.
- `remainingMonths ≤ 0` → `DUE`; `remainingMonths ≤ окно` → `SOON`; иначе `OK`.

Итоговый статус — худший из двух. Если срока по времени нет, `remainingMonths = null` и статус берётся по пробегу.

#### Сортировка (`SortedTaskStatsUseCase`)

Сначала `DUE`, затем `SOON`, затем `OK`; внутри одного статуса — по возрастанию `remainingKm`.

#### Пример

Toyota Camry, пробег 152 000 км, сегодня 08.10.2026.

| Работа | Параметры | Срок на | Осталось | Статус |
|---|---|---|---|---|
| Свечи зажигания | 40 000 км, последний раз на 110 000, окно 2 000 | 150 000 км | −2 000 км | `DUE` |
| Замена масла и фильтра | 10 000 км / 12 мес, последний раз на 143 000 км 20.11.2025, окно 1 000 | 153 000 км | 1 000 км / 2 мес | `SOON` |
| Салонный фильтр | 20 000 км, последний раз на 135 000, окно 2 000 | 155 000 км | 3 000 км | `OK` |

- Масло: по пробегу остаток равен окну → `SOON`; по времени прошло 10 полных месяцев, осталось 2, окно `round(12 × 1 000 / 10 000) = 1` → `OK`; итог — худший, `SOON`.
- `SortedTaskStatsUseCase` вернёт работы в порядке: свечи, масло, салонный фильтр.
- `CarAlertsUseCase` вернёт `soon = 1`, `due = 1`, `taskCount = 3`; отсюда `total = 2`, `worstStatus = DUE`.

### Машины

| Use case | Вход | Выход | Правила |

Название, VIN и пробег правятся на экране машины по одному, работы — по одной на экране работы. Форма авто только добавляет машину.

#### `AddCarUseCase`

- Возвращает `null` и ничего не сохраняет, если марка пустая или пробег не положительный.
- Марка обрезается по краям; пустые VIN и номер сохраняются как `null`; номер приводится к виду, описанному у `Car.plate`.
- Работы проходят `NormalizeTaskUseCase`; отклонённые отбрасываются.
- Работу по умолчанию use case не подставляет: её подставляет форма авто, если блоков работ нет, — с «последний раз» = текущий пробег. Сам use case сохраняет машину без работ, если список пуст.

#### `NormalizeTaskUseCase`

Общие правила для работы, введённой в форме авто или на экране работы, — при добавлении авто, добавлении и правке работы.

- Возвращает `null`, если название пустое или интервал по пробегу `≤ 0`.
- Название обрезается по краям.
- Работе без окна напоминания ставится 15 % её интервала по пробегу.
- `intervalMonths ≤ 0` считается отсутствующим; `lastDoneDate` сохраняется только у работ с интервалом по времени.

#### `MarkTaskDoneUseCase`

- Пустые строки сервиса и комментария и неположительная стоимость сохраняются как `null`.
- Вызывает `CarRepository.markTaskDone`: работа и запись истории меняются одной транзакцией. `false`, если нет машины или работы.

#### Правило «работа отмечена» (`DoneMarksUseCase`)

Работа считается отмеченной, пока одновременно:

- у неё есть запись истории, созданная отметкой (`taskId` этой работы, `prevLastDoneKm` заполнен), с пробегом, равным текущему пробегу машины;
- `lastDoneKm` работы равен этому же пробегу, то есть работу после отметки не меняли.

Как только пробег машины изменился, отметка перестаёт действовать: снять её нельзя, работу можно отметить заново. Пробеги сравниваются на точное равенство в километрах. Признак приходит на экран машины вместе с состоянием работы.

#### `UnmarkTaskDoneUseCase`

Находит запись, которая держит отметку (`DoneMarksUseCase`), и вызывает `CarRepository.unmarkTaskDone`: работа возвращается к прежним `lastDoneKm` и `lastDoneDate`, запись удаляется — одной транзакцией. `false` и ничего не меняет, если машины нет или работа не отмечена.

#### `UpdateHistoryEntryUseCase`

- Меняет у записи дату, пробег, стоимость, сервис и комментарий; название работы, машина и данные для отката не меняются.
- Пробег `≤ 0` или запись, которой нет, — `false`, ничего не сохраняется. Пустые строки и неположительная стоимость сохраняются как `null`.
- Если у записи, созданной отметкой, изменился пробег, а «последний раз, км» её работы всё ещё равен прежнему пробегу записи (работу после отметки не меняли), работа получает новый пробег записи — одной транзакцией с записью. Дата работы не меняется. В остальных случаях работа не трогается.
- После смены пробега запись перестаёт удовлетворять правилу «работа отмечена»: отметка пропадает без отката. Смена только даты, сервиса, стоимости или комментария на отметку не влияет.
- Работает и для записей проданной машины.

#### `AddHistoryEntryUseCase`

- Ручная запись — работа, сделанная раньше, например до установки приложения. Сохраняется без `taskId` и данных отката: работы не меняются, отметкой запись не считается.
- Только для действующей машины; машины нет или она продана — `false`. Пустое название или пробег `≤ 0` — тоже `false`, ничего не сохраняется.
- Название обрезается по краям; пустые строки сервиса и комментария и неположительная стоимость сохраняются как `null`.

#### `SetDefaultCarUseCase`

- С `carId` — эта машина становится выбранной.
- Включение без выбранной (или без существующей выбранной) машины выбирает последнюю открытую, а если её нет — первую в списке.

#### `ForgetCarInSettingsUseCase`

Вызывается после удаления машины — с её экрана или полного.

- Если это последняя открытая машина, `lastOpenedCarId` очищается.
- Если это выбранная машина, на её место выбирается последняя открытая, а если её нет — первая из оставшихся; `openDefaultCar` не меняется.
- Если машин не осталось, `defaultCarId` очищается и `openDefaultCar` выключается.

#### `SyncRemindersUseCase`

- Читает сохранённый план; записи с временем показа в прошлом по ещё существующим работам считает показанными и берёт последнюю на каждую работу.
- Строит новый план через `PlanRemindersUseCase`.
- Сохраняет «последние показанные + новый план» (`ReminderRepository.replaceRecords`) и передаёт новый план в `ReminderScheduler.schedule`.
- Вызывается из `AppViewModel` при запуске приложения и после каждого изменения машин или настроек.
- Показанным считается всё, что было запланировано и чьё время прошло; доставило ли уведомление система (например, при отозванном разрешении), domain не знает.

## Единицы расстояния

- Все расстояния в моделях и в базе — в километрах.
- При выбранных милях экран показывает значение как `round(км / 1.609344)` и принимает ввод в милях; в километры ввод переводится как `round(мили × 1.609344)` (`ui/format`).
- Расхождение в ±1 км из-за округления допустимо. Исключение — нетронутое поле: если введённое число равно показанному, сохранённые километры не пересчитываются (`keepKm`). Правило «работа отмечена» сравнивает пробеги на точное равенство, и сдвиг на километр при простом открытии и сохранении работы снимал бы отметку.
- Фильтр истории сравнивает пробег записи в выбранных единицах с введённым диапазоном.

## Открытые вопросы

- Машину с пробегом 0 добавить нельзя (так в макете). Для нового авто это может быть неудобно.
- Где подставляется работа по умолчанию при пустом списке работ: название локализуется, поэтому в domain его нет.
- Сброс ссылок в настройках (`ForgetCarInSettingsUseCase`) идёт после удаления машины, отдельной транзакцией. Сбой между ними оставит ссылку на удалённую машину; читающие use case-ы это переживают — проверяют, что машина есть.
