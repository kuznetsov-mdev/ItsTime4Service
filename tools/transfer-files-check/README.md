# Native transfer file checks

The Android `transferCheck` variant uses `.transfercheck` as its application ID suffix and an independent sandbox. Its own share recipient is available only in that variant. Normal app sources contain no test entry point. The iOS harness is generated under `/private/tmp/it4s-transfer-ios-check` with a separate `.filescheck` bundle ID and local ad-hoc simulator signing (no account or certificate). It exposes its own synthetic Documents folder to the system Files UI; production Info.plist does not enable file sharing.

Build `:androidApp:assembleTransferCheck` and `:shared:linkDebugFrameworkIosSimulatorArm64` through the project's `gradle-run` skill. Install only the check APK on a test emulator. `python3 tools/transfer-files-check/run_android.py` checks cancellation of all three dialogs, system save/open for both files, and selected-target handoff to its own recipient. Only whitelisted labels/resource identifiers appear in diagnostics. It never takes screenshots or opens unrelated files. The script expects emulator-5554 and a dedicated Download/TransferFilesCheck folder.

`python3 tools/transfer-files-check/run_ios.py --device <simulator-UUID>` generates/builds a separate Xcode project and runs XCTest on the explicitly selected installed simulator. `--only` selects one known case. A pure UIKit control requires a cancellation callback, not only a successful tap. Zero executed tests fails the runner. It checks cancellation, system export/open for both fixtures and sharing through Save to Files, then reopens the shared file and verifies SHA-256. Each test uses unique output names and retains saved fixtures. System actions are scoped to native navigation bars; document selection taps a file cell; the share action accepts system cells as well as buttons. Cancellation uses an actual Cancel button or the sheet-dismiss gesture. The stale `Other` element named Cancel can overlap More and must not be tapped. The generated test plan sets `uiTestingScreenshotsLifetime` and `userAttachmentLifetime` to `keepNever`; the runner rejects retained screen attachments, including on failed tests. Automatic failure diagnostics are disabled. The runner stores full temporary Xcode logs privately and prints only bounded compiler/test diagnostics and numerical result summaries. Run native Gradle tests and XCTest serially when they target the same simulator. GUI attachment can be necessary for simulator accessibility.

Plain.it4s and Protected.it4s contain a synthetic one-car template. The encrypted fixture was independently generated with Apple CommonCrypto PBKDF2-HMAC-SHA256 and CryptoKit AES-GCM, using fixed test-only salt/nonce. The non-secret test password is `Synthetic-file-check`. Never reuse fixed parameters in production; production providers retain their random salt/nonce policy. TransferFileFixtureTest authenticates/decrypts the bytes against both real providers and checks the decoded model. Each system roundtrip verifies SHA-256 of the saved/read bytes, not only a callback label.

No screenshots, accounts, network destinations or user application databases are needed. Saved synthetic files and test result bundles are retained; these scripts do not delete them. Removing a test app/emulator/results requires separate authorization.

Run the current acceptance investigation sequentially on one simulator at a time. Before a run, explicitly confirm the selected device is booted (`xcrun simctl bootstatus <UUID> -b`) and has an attached DeviceHub window. The runner does not yet enforce this prerequisite. Generate the project once with `prepare_ios.py`; `--skip-prepare` reuses it. Derived data and result bundles are isolated per device/run, but the latest concurrent runs encountered bootstrap failures and are not evidence of a stable matrix. Do not overlap framework rebuilding or native KGP tests with an active XCTest run on the same device. Files warmup is repeated for each scenario. Menu matching accepts Russian grammatical variants and Unicode whitespace in Save to Files. Follow the latest unresolved cases in `docs/research/transfer-files-verification.md`.
