# Native transfer file checks

The Android `transferCheck` variant uses `.transfercheck` as its application ID suffix and an independent sandbox. Its own share recipient is available only in that variant. Normal app sources contain no test entry point. The iOS harness is generated under `/private/tmp/it4s-transfer-ios-check` with a separate `.filescheck` bundle ID and local ad-hoc simulator signing (no account or certificate). It exposes its own synthetic Documents folder to the system Files UI; production Info.plist does not enable file sharing.

Build `:androidApp:assembleTransferCheck` or the isolated minified `:androidApp:assembleTransferReleaseCheck` and `:shared:linkDebugFrameworkIosSimulatorArm64` through the project's `gradle-run` skill. Install only the check APK on a test emulator. `python3 tools/transfer-files-check/run_android.py` checks cancellation of all three dialogs, system save/open for both files, and selected-target handoff to its own recipient. The Crypto action also authenticates the independent protected fixture, encrypts it with the production codec and decodes it again. The runner requires Crypto PASS before file checks. Only whitelisted labels/resource identifiers appear in diagnostics. It never takes screenshots or opens unrelated files. The script expects emulator-5554 and a dedicated Download/TransferFilesCheck folder.

`python3 tools/transfer-files-check/run_ios.py --device <simulator-UUID>` generates/builds a separate Xcode project and runs XCTest on the explicitly selected installed simulator. `--only` selects one known case. A pure UIKit control requires a cancellation callback, not only a successful tap. Zero executed tests fails the runner. It checks cancellation, system export/open for both fixtures and sharing through Save to Files, then reopens the shared file and verifies SHA-256. Each test uses unique output names and retains saved fixtures. Short unique run-folder names sort first. Back is matched by its exact label, excluding the Actions Menu title; iOS18 does not expose the BackButton identifier used by iOS27. After entering a folder the test waits again for the native save action to become hittable. System actions are scoped to native navigation bars; document selection taps a file cell; the share action accepts system cells as well as buttons. Cancellation uses an actual Cancel button or the sheet-dismiss gesture; a share popover is dismissed by a tap outside it. The stale `Other` element named Cancel can overlap More and must not be tapped. The generated test plan sets `uiTestingScreenshotsLifetime` and `userAttachmentLifetime` to `keepNever`; the runner rejects retained screen attachments, including on failed tests. Automatic failure diagnostics are disabled. The runner stores full temporary Xcode logs privately and prints only bounded compiler/test diagnostics and numerical result summaries. Run native Gradle tests and XCTest serially when they target the same simulator. GUI attachment can be necessary for simulator accessibility.

Plain.it4s and Protected.it4s contain a synthetic one-car template. The encrypted fixture was independently generated with Apple CommonCrypto PBKDF2-HMAC-SHA256 and CryptoKit AES-GCM, using fixed test-only salt/nonce. The non-secret test password is `Synthetic-file-check`. Never reuse fixed parameters in production; production providers retain their random salt/nonce policy. TransferFileFixtureTest authenticates/decrypts the bytes against both real providers and checks the decoded model. Each system roundtrip verifies SHA-256 of the saved/read bytes, not only a callback label.

No screenshots, accounts, network destinations or user application databases are needed. Saved synthetic files and test result bundles are retained; these scripts do not delete them. Removing a test app/emulator/results requires separate authorization.

Run the current acceptance investigation sequentially on one simulator at a time. The runner now holds a nonblocking lock, waits for the selected device to boot (`xcrun simctl bootstatus <UUID> -b`) and requests its DeviceHub window before XCTest. A process-group watchdog bounds a single case to 360 seconds and a full matrix to 1200 seconds. Each test has its own retained Run-<token> folder. Share cancellation handles both sheets and popovers. Generate the project once with `prepare_ios.py`; `--skip-prepare` reuses it. Derived data and result bundles are isolated per device/run, but the latest concurrent runs encountered bootstrap failures and are not evidence of a stable matrix. Do not overlap framework rebuilding or native KGP tests with an active XCTest run on the same device. The harness opens the native picker/share UI directly; no extra DocumentsApp launch is needed. The earlier repeated warmup itself caused bootstrap failures on iOS27. Menu matching accepts Russian grammatical variants and Unicode whitespace in Save to Files. Follow the latest unresolved cases in `docs/research/transfer-files-verification.md`.

`prepare_upgrade.py` extracts the tracked 1.0.0 baseline into a fresh temporary directory and generates a shared Gradle init script with a unique upgradeCheck application suffix. Build both old and current `:androidApp:assembleUpgradeCheck -I <init>` through gradle-run. Install the old APK only in that new sandbox, create synthetic records, then install the new APK with `adb install -r`; never clear app data or touch the normal application. The baseline uses local.properties only by symlink/path; the helper never reads or prints it. Metadata and APKs are retained.

TransferExchangeTest emits complete synthetic backup/template documents from both production crypto providers. TransferPeerFiles retains the emitted peer bytes; both platforms authenticate, import through SQLite and compare restored content/settings/rollback. The public test-only password is Synthetic exchange ñ Тест. Android R8 requires narrow keep rules for JCA algorithm registrations loaded by name (AES/PBEPBKDF2/SHA256); the Crypto action verifies the actual minified provider rather than relying on compilation.

Use --step crypto for a short production-codec check after a rebuild; --apk accepts only the known isolated transferReleaseCheck path. A full run verifies the codec plus the six file cases.
