**Черновик. Вторая итерация анализа от 06.11.2026. Документ не утверждён.**

Продолжение [первой итерации](export-import-iteration-1.md). Факты о модели, связях истории, порядке записей и отсутствии файловых адаптеров переиспользуются из её раздела 2; повторный обход кода не выполнялся. Источник решений — ответы пользователя Q1–Q14, переданные координатором. Новые рекомендации не считаются согласованными. Код, макет, действующие спецификации и общий план не меняются.

## 2. Обновлённый scope и существенные сценарии

1. **Полная личная копия:** все сохранённые данные, включая проданные авто, служебные связи/порядок истории и настройки. Восстановление с предпросмотром: замена либо объединение. Системные очереди уведомлений не копируются, разрешения ОС не переносятся.
2. **Выборочная передача авто:** по умолчанию марка и выбранные работы, без личных фактов обслуживания. Дополнительные группы данных явно включает отправитель. В режиме по умолчанию это обмен регламентом; с дополнительными полями файл уже содержит личные данные, его нельзя называть обезличенным. Предлагается единый сценарий передачи с составом файла, а не автоматическое включение личных данных в любой регламент.
3. **Импорт выборочного файла:** получатель видит фактический состав, выбирает новую/существующую машину и работы; лично относящиеся поля применяются только явно. Отсутствующее в файле поле не означает очистку существующего поля. Применимость/источник отображаются как сведения автора, а не как подтверждение производителя.
4. **Объединение:** новые сущности добавляются; при совпадениях/изменениях нужен выбор. Отсутствие сущности в старой копии не доказывает её удаление на другом устройстве. В коде нет истории изменений для автоматического определения «самой новой» версии: больший пробег тоже не всегда вернее, поскольку его могли исправить.
5. **Неизвестные сведения:** для новой работы не выдумываются последний пробег/дата; используется принятый рекомендательный статус. Но обязательный текущий пробег новой машины — отдельная неясность Q20. Для существующей машины не включённые в файл сведения сохраняются.
6. **Автокопирование:** после первоначальной настройки создаёт полные личные снимки; ручное сохранение доступно всегда. До выбора места и способа защиты нельзя показывать, что данные уже защищены. Для каждой попытки различаются формирование снимка, подтверждённая запись файла и ошибка/ожидание.

Полное восстановление и передача регламента остаются разными по смыслу: при первом переносится собственное состояние, при втором сведения отправителя не должны автоматически становиться историей получателя. Включение истории/пробега в выборочную передачу разрешено Q3, но порядок их применения требует Q17–Q19.

## 3. Проверенные ограничения платформ

Официальные источники проверены 06.11.2026; перед реализацией конкретные API проверяются повторно.

- На Android Storage Access Framework даёт доступ к выбранным документам/папке; для сохранения доступа после перезапуска нужен сохраняемый grant. Перемещение/удаление документа может сделать доступ недействительным. Документы вне app-specific каталога сохраняются после удаления приложения. [Android Documents and files](https://developer.android.com/training/data-storage/shared/documents-files).
- WorkManager не обещает точное время запуска периодической работы: оно зависит от ограничений и оптимизаций ОС. [Android Work requests](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work).
- На iOS `earliestBeginDate` — только нижняя граница, система не гарантирует запуск в указанное время. [Apple earliestBeginDate](https://developer.apple.com/documentation/backgroundtasks/bgtaskrequest/earliestbegindate).
- iOS document picker предоставляет security-scoped доступ к выбранной папке; для последующего доступа используется bookmark. [Apple Directory access](https://developer.apple.com/documentation/uikit/providing-access-to-directories).

**Вывод аналитика:** автокопия в 1.1.0 возможна, но нельзя обещать точное время или неизбежный запуск при закрытом приложении. Надёжная продуктовая формулировка — «при первой доступной возможности», с проверкой незавершённого сохранения при следующем открытии. Системная папка может обслуживаться внешним облачным провайдером по выбору пользователя; приложение не создаёт собственное облако. Для гарантированно локальной работы выбирается локальная папка. Внутренняя копия в контейнере приложения не заменяет переносимый файл на случай удаления приложения/потери устройства.

## 4. Технические предложения команде

Не требуют выбора библиотеки или формата JSON пользователем; детали позже фиксируются в контракте и тестах.

- У файла есть версия, тип и явный перечень включённых групп. «Не экспортировалось», «пусто» и «неизвестно» — разные состояния; в merge не очищать поля, которых нет в файле.
- Полная копия сохраняет идентичность и порядок. Для выборочного регламента не использовать марку как уникальный идентификатор и не переносить привязку к автомобилю отправителя как автоматическую команду перезаписи.
- Применение подтверждённого плана импорта транзакционно. Предпросмотр проверяется на актуальность перед записью; ошибка не оставляет полузаменённую базу. Источниковые UUID, соответствия получателя и идентичность файла нужны для повторяемого импорта без произвольного дублирования.
- Отсутствующие в копии сущности при объединении не удаляются. Одинаковая марка/VIN — повод для проверки, а не безусловное доказательство тождества. История удалённых работ остаётся допустимой, как установлено в первой итерации.
- Уточнить конфликт состояния «продан/действующий» как изменение данных машины и показывать последствия до подтверждения; не удалять работы или не возвращать машину в действующие молча.
- Для чистого регламента Q12 применяется к новым работам. При личном полном восстановлении индивидуальные пороги сохраняются как часть данных. У существующей работы изменение параметров и изменение факта обслуживания — разные решения.
- Порядок, ссылки и данные отмены старых отметок требуют отдельной проверки после merge. Нельзя автоматически совмещать несовместимые цепочки обслуживания. Пользовательский эффект — Q26.
- Для автокопий объединять частые изменения, пропускать неизменённый снимок, показывать последнюю успешную копию и ошибку/потерю доступа. Не подменять неудачное сохранение новой датой успеха. Новая копия сначала должна быть полностью записана и проверена; ротация касается только принадлежащих приложению автокопий, а не ручных пользовательских файлов.
- Пароль/ключ для автоматического шифрования не входит в переносимую копию, код, логи или обычные настройки. Предлагается защищённое хранилище ОС, но его использование и поведение при недоступности требуют Q25. Сам секрет в аналитике не запрашивается и не читается.
- Настройки автокопирования логически входят в пользовательские предпочтения, но на другом устройстве путь и сохранённый ключ доступа нельзя считать действующими: после переноса требуется местная настройка. Это не отменяет Q6 о восстановлении остальных настроек.

## 5. Новые вопросы владельцу продукта

Нумерация продолжается после Q14. Достаточно номера и варианта; вопросы задаёт координатор карточками по 2–3, без дополнительных сообщений во время выбора.

**Q15. Как распознавать ту же машину, если у неё другой внутренний идентификатор или есть только одинаковая марка?**

- **А — показать возможные совпадения и попросить выбрать «Это моя машина» либо «Добавить отдельную» (рекомендую).** Общая марка сама по себе не объединяет чужие автомобили.
- Б — автоматически сопоставлять по VIN, а остальные совпадения спрашивать. Быстрее, но ошибочный/повторённый VIN может привести к неверному объединению.
- В — при разных идентификаторах всегда создавать отдельную машину. Проще, но при переносах будет больше копий.

**Q16. Какие варианты предлагать для уже имеющейся работы при применении чужого регламента?**

- **А — «Пропустить», «Обновить параметры работы», «Добавить отдельную»; по умолчанию пропустить (рекомендую).** Обновление параметров регламента сохраняет собственное обслуживание/историю получателя; личные включённые факты рассматриваются отдельно по Q17. Точный состав параметров фиксируется в контракте, отдельное новое поле описания работы здесь не вводится.
- Б — только «Пропустить» или «Добавить отдельную», без обновления параметров. Меньше риск перезаписи, но интервалы придётся менять вручную.

**Q17. При объединении личных копий как решать разногласия пробега, последнего обслуживания и отредактированных записей истории?**

- **А — показывать каждое существенное разногласие и предлагать «Оставить текущее» / «Взять из файла», по умолчанию сохранять текущее (рекомендую).** Новые непротиворечивые сведения добавляются; пользователь контролирует изменения фактов.
- Б — один общий выбор для всех конфликтов: предпочитать текущие данные или файл, с итоговым предпросмотром. Меньше действий, но выше риск пропустить важное различие. Отсутствие данных в файле всё равно не означает удаление.

**Q18. При выборочном экспорте отделяем последнее обслуживание работ от истории?**

- **А — отдельные выключенные по умолчанию группы «Последнее обслуживание работ» и «История» (рекомендую).** Можно передать известный исходный пробег/дату работы без личного журнала и наоборот. При непереданном обслуживании новые работы получают «Не знаю».
- Б — переносить последнее обслуживание вместе с включением истории. Проще переключатели, но эти два вида сведений уже нельзя выбрать независимо. В режиме по умолчанию оба не передаются при любом варианте.

**Q19. Что входит во включаемую историю при выборочной передаче авто?**

- **А — даты, названия и пробеги; стоимость, сервисы и комментарии включаются дополнительной отдельной группой (рекомендую).** Больше контроля над личными подробностями; обе группы по умолчанию выключены.
- Б — сразу вся история со стоимостью, сервисами и комментариями; состав явно подписан перед передачей. Меньше переключателей, но отправителю нужно внимательнее проверить содержимое.

**Q20. Если в файле нет текущего пробега, что делать при создании новой машины?**

- **А — попросить фактический пробег перед сохранением новой машины (рекомендую).** Один обязательный ввод; ноль не подставляется. У существующей машины собственный пробег сохраняется.
- Б — позволить создать машину с неизвестным текущим пробегом. Удобнее отложить ввод, но состояние неизвестного пробега машины и связанные ограничения расчётов тоже входят в 1.1.0; это шире уже согласованного неизвестного последнего обслуживания работы.

**Q21. Нужен ли пароль по умолчанию у выборочного файла, если отправитель включил личные данные?**

- **А — да, как у полной копии: включён по умолчанию, можно явно отключить (рекомендую).** Чистый регламент по умолчанию остаётся без пароля; история/пробег/последнее обслуживание/VIN/госномер делают файл личным.
- Б — пароль обязателен для любого такого личного файла. Защита строже, но пароль нужно передавать получателю отдельно.
- В — пароль по умолчанию только у полной копии; для выборочного файла его предлагают включить вручную. Меньше запросов, но проще случайно отправить открытые личные сведения.

**Q22. Куда сохранять автоматические копии?**

- **А — в выбранную пользователем папку через системные «Файлы» (рекомендую).** Требуется первоначальный выбор и доступ; при потере доступа копирование явно ждёт настройки. Локальная папка работает без сети, внешний провайдер может иметь собственные условия.
- Б — во внутреннее хранилище приложения, а наружу пользователь выносит копию вручную. Меньше настройки, но такие копии не защищают от удаления приложения или потери устройства; это должно быть явно показано.
- В — внутренние копии плюс автоматическая запись в выбранную папку. Дополнительная страховка при недоступности папки, но больше места и два отдельно отображаемых результата сохранения.

**Q23. Когда автоматически создавать копию?**

- **А — после изменений, объединяя частые изменения; сохранять при первой доступной возможности, включая следующее открытие (рекомендую).** Меньше несохранённых изменений, точное фоновое время не обещается.
- Б — не чаще раза в день при наличии изменений и возможности выполнить сохранение. Меньше файлов, но изменения текущего дня могут ещё не попасть в копию.
- В — пользователь выбирает периодичность в настройках. Больше гибкости и UI; ограничения ОС всё равно не позволяют гарантировать точное время при закрытом приложении.

**Q24. Сколько автоматических копий хранить?**

- **А — актуальную и по одной за 7 последних дней с изменениями (рекомендую).** Есть несколько точек возврата; более старые собственные автокопии ротируются только после успешной новой записи.
- Б — актуальную и по одной за 30 последних дней с изменениями. Больше глубина восстановления и расход места.
- В — хранить все до ручной очистки. Ничего не удаляется автоматически, но место не ограничено. Ручные экспортированные файлы не затрагиваются ротацией при любом варианте.

**Q25. Для автоматических копий с паролем можно ли сохранять ключ защиты в защищённом хранилище устройства?**

- **А — да, после согласия при настройке (рекомендую).** Автокопии шифруются без повторного ввода; для переноса на другое устройство нужен пароль владельца. При недоступности ключа задача ждёт, а не сохраняет открытый файл.
- Б — ключ не сохранять: защищённое копирование ждёт ручного ввода пароля при открытии приложения. Секрет не запоминается, но полностью автономного защищённого копирования не будет; открытые автокопии возможны только после явного отключения защиты по Q4.

**Q26. Сохранять ли отмену старой отметки «Выполнено» после объединения разошедшихся данных?**

- **А — сохранять там, где данные работы и связанной истории не конфликтовали; при конфликте сохранять историю, но прежнюю отметку не разрешать откатывать (рекомендую).** Новые отметки после импорта отменяются как обычно; при полном замещении согласованной копией старый откат сохраняется.
- Б — после любого объединения отменять можно только новые отметки, прежняя история остаётся. Проще объяснить единое правило, но ограничение затрагивает и работы без конфликтов.

## 6. Следующая итерация

Дождаться ответов Q15–Q26 через координатора, не запускать реализацию. После ответов уточнить только оставшиеся развилки и затем подготовить согласуемые сценарии/критерии и контракт файлов. Пункты Q2, Q3 и Q14 уже входят в scope: объединение, выборочная личная передача и автоматические копии не откладываются без нового решения пользователя.
