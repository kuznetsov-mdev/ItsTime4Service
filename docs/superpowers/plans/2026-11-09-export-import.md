# Export and import 1.1.0 Implementation Plan

> Выполнять после пользовательского просмотра исправленного макета и подтверждения постановки, по этапам с проверяемым результатом. Следовать проектному процессу «макет → спецификация → согласование → код». Для актуализации плана доступен `writing-plans`, для Gradle — `gradle-run`, для подтверждения результатов — `verification-before-completion`. Делегирование — только в согласованном с пользователем режиме.

**Goal:** Реализовать ручные резервные копии и выборочный перенос машины между Android/iOS без потери фактов обслуживания.

**Architecture:** Отдельные границы для согласованного снимка БД, переносимого кодека, шифрования, чистого плана конфликтов и системных файлов. UI показывает план до записи; применение атомарно и отделено от настройки уведомлений.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform, Koin, SQLDelight/SQLite, существующие commonTest/Robolectric. Сериализация и криптопровайдер добавляются только после проверки шага 1, с фиксацией версии в каталоге и таблице библиотек.

**Spec:** [Постановка на разработку](../../../specs/export-import.md), [согласованные требования](../../research/export-import-iteration-3.md), [макет](../../index.html#interactiveApp).

**Status:** Реализация запущена пользователем 10.11.2026 после ревью макета и постановки. Реализованы этапы 2–4: неизвестное обслуживание, согласованный снимок и рабочий кодек/конверт/шифрование. Последний полный Android suite — 574 теста (проверка перед коммитом, sequence 25), R8 и debug APK — PASS; iOS — 55 transfer-тестов, обе production/test compilation и debug/release frameworks — PASS без предупреждений. Дополнительно 4 новых теста границ валидатора прошли отдельно на каждой платформе. [Отчёт этапа 4](../../research/transfer-codec-verification.md). Пользователь явно разрешил продолжать разработку, перенеся реальный API24 в обязательные проверки перед релизом. Уточнён выбор конкретной работы среди одноимённых; макет/контракт обновлены, 22 JS-проверки — PASS. Следующий этап — планирование и атомарное применение импорта; файлы/UI и release gates ещё не завершены.

## Global Constraints

- Android API 24+ и существующие iOS targets, перенос Android ↔ iOS. Не повышать минимальные ОС скрыто.
- Только ручные действия, бюджет сервисов нулевой, своей сети/аккаунтов/облака нет.
- По умолчанию передаются марка и работы; личные группы включаются явно. История и последнее обслуживание независимы.
- Личные файлы защищены по умолчанию с явным отключением; пароль/ключ не сохраняются между операциями и не попадают в логи, route или saved state.
- Восстановление: замена либо объединение; предпросмотр; текущие данные по умолчанию при конфликте; страховочная копия перед заменой предлагается, но не обязательна.
- Никаких автоматических коммитов/пушей. Работать в текущей ветке. Запуски Gradle только через `gradle-run`.

## Review Focus

- Исключённая группа не очищает имеющееся поле; пустое и неизвестное значение не смешиваются с отсутствующей группой.
- Восстановление сохраняет порядок одинаково датированной истории, проданные авто, записи удалённых работ и допустимый откат отметок.
- Повторное подтверждение, смерть процесса после commit и новые изменения после предпросмотра не создают повторный/устаревший импорт.
- Неверный пароль, большой/повреждённый файл, отмена и отказ доступа не меняют текущую БД и не раскрывают личное содержимое.
- Неизвестное обслуживание не подменяется нулём и не скрывает известную просрочку по другому критерию.
